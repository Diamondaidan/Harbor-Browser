Source archives passed decompression/CRC, version checks and privacy-path review. Historical Git source mirrors were verified against every original source blob. Uploaded asset sizes and SHA-256 digests were checked before publication. Older applications were not rebuilt or installed for this archive audit.

## Recovery limits

The 0.3.1 entry has the exact original corrected 93,245-byte source ZIP; its original compiled installer was not recovered.

The 0.6.0 release also preserves its [initial original source snapshot](https://github.com/Diamondaidan/Harbor-Browser/releases/download/v0.6.0/HarborBrowser-0.6.0-source-initial.zip), alongside the later source package with public licensing/dependency notices. The extra original has its own checksum file.

Documented earlier originals remain unavailable: 0.1.1, 0.2.0, 0.2.1, 0.2.2, 0.2.3, 0.3.0. This archive does not claim complete recovery of every early Harbor version.

Explicit experimental, preview, beta, development, release-candidate and unfinalized staging builds are outside this full-release archive. The complete 0.4.1 hotfix and 0.6.1 UI/Proton-off revisions have their own entries, preserving different original files with the same base application version.

## Distribution and validation

Windows installers remain unsigned. Harbor-authored code is GPL-3.0-only; third-party components retain their original terms. Supplemental license/archive notes accompany older original ZIPs without changing those files.

The final 0.7.0 package passed 1,612 release assertions across 22 suites, 94 core and 104 full-payload installer fixture checks, and 403 packaged application assertions. Installed RC1 observations are documented separately. Physical internet/power recovery, final installed upgrade, clean/offline spare-PC installation and protected IPv6 remain unconfirmed; see the 0.7.0 validation report. Hosted feed verification checks metadata and hashes, not an installed end-to-end update.

## Recommended next milestone

0.7.1 should focus on release/update reliability: cover upgrades from older Harbor releases, distinguish release candidates from full builds, test the public update path with retained user data, and finish physical recovery and clean-PC checks. Keyboard focus and accessibility improvements can follow that release validation work.

Source inspection found two concrete follow-ups: the markerless-install upgrade allowlist currently recognizes only the archived 0.5.3 executable, and the updater requires a greater version number, while RC1 and the full 0.7.0 application report the same 0.7.0 version. These are code observations, not newly executed installed-upgrade tests.
